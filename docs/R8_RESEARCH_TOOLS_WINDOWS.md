# R8: продолжение исследования на Windows без изменения R7

Предоставленный baseline уже сохранён; присылать тот же lock повторно не нужно. CoreSHA совпал с артефактом R7. Сам R7 и его миры этим набором **не редактируются**. Программы не создают игровой профиль и не устанавливают аддоны.

## 1. Получить набор

Распаковать отдельный `Reimagined-R8-Research-Tools.zip` в `C:\Games\Reimagined-R8-Research`. Достаточно уже используемого Python3.11+ (`py -3 --version`); Git/Gradle/Java для этого исследования не нужны. Внутри — только собственные скрипты, исходный исследовательский список и замороженный предоставленный lock, никаких игровыхJAR.

## 2. Проверить точные модули Mekanism (партия A, ещё не установка)

```powershell
Set-Location C:\Games\Reimagined-R8-Research
py -3 scripts/r8/probe_party_a.py --r7-downloads C:\Games\Reimagined-r7\downloads --output C:\Games\R8-Party-A-Evidence.json
```

Сначала скрипт читает точный базовыйMekanism из предоставленногоR7lock: копирует его из старогоdownloadcache при наличии, иначе скачивает тот же официальный файл. Сверяет также SHA256 из lock и читает реальную игровуюверсию изJAR. Версия каталога и version вmanifest могут отличаться — это не считается равенством по предположению. Затем скрипт ищет **только10.7.19.85**, с тем же каналомrelease, Minecraft1.21.1/NeoForge. Использует IDs из проверенных publisher-исходников: GeneratorsOFVYKsAk, ToolstqQpq1lt, Additionsa6F3uASn. Не берёт latest и не меняет базовыйMekanism.

Из официальногоAPI берутся URL/размер/хеши и лицензияMIT; скачивание идёт общим провереннымTransport. После проверки официальногохеша читаются **реальныеJAR**: производственныйmodId, версия изmanifest, compiledclasses и точное требование baseMekanism той же полнойверсии, платформенные ограничения. Непроверенная дополнительнаябиблиотека/JarJar останавливает Metadata-приёмку; верхнийрегистрREQUIRED не игнорируется. Архивы не запускаются и не распаковываются в игровые каталоги.

Кэш создаётся новый: `C:\Games\R8-Party-A-Evidence-artifact-cache`. СтарыеR7/R4–R6кэши не трогаются. Если такойкэш/output уже есть, выберите новое имяJSON. Это сохраняет предыдущуюпопытку для разбора. На403 или отсутствие точного файла не подставляется другойсайт/версия.

Если все проверки прошли, результат может иметь **VERIFIED_METADATA**, но всегда `runtime_verified=false`, `installed=false`. Это не разрешение назвать партии рабочими и не замена будущих GameTests/клиента/сервера/сохранений. Точная копия базовогоJAR и бинарники модулей остаются в исследовательскомкэше, не копируйте их самостоятельно в R7.

## 3. Сведения остальных20кандидатов из каталога

```powershell
py -3 scripts/r8/research_addons.py --r7-lock C:\Games\Reimagined-r7\installed.lock.json --output C:\Games\R8-All-Addons-Catalog.json
```

Это только API-метаданныеModrinth, без загрузкиJAR. Для неподтверждённыхназваний требуется уникальное точное совпадение; похожийпроект не выбирается. Записи не получают VERIFIED_METADATA/RUNTIME_VERIFIED автоматически. Наличиеверсий вкаталоге не проверяет CreateABI, Sable-физику, лицензии вложений, SHA256 реальныхбайтов и совместимостьмагическихпортов. ДляCF/GitHub-onlyцелей требуется отдельнаяпроверка; отсутствиеModrinthрезультата не означает отсутствиемода.

## 4. Вернуть свидетельства

Прикрепите `R8-Party-A-Evidence.json` и при возможности `R8-All-Addons-Catalog.json`. Не нужно отправлятьJAR илимиры. Код завершения2 означает, что не все три модуля прошли проверку метаданных; код0 не означает успешную игру. Ошибки каждого проекта сохраняются вJSON; успешныйрезультат фикстурных unit-тестов не выдаётся за ваш сетевойпрогон.

После получения и проверки этих данных можно завершить бинарноеисследование и выбрать первуюпартию по docs/R8_INTEGRATION_PLAN.md. До этого сохраняются ограничения задания: нет новых модов вR7, нетновыхквестов на отсутствующиеаддоны, нетArsNouveau и нетавтоматическойподменыThaumcraft/Botania.
