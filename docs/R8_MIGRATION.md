# R7 → R8: сохранения и воспроизводимость

## Состояние сейчас

Ничего не мигрировалось. Полный Windows lock и мир недоступны в облаке. R7 исходники/tag/локальныйпакет зафиксированы в pack/r8/r7-source-snapshot.json, но это **не** полный установленный R7. Старые25пинов не подтверждают Create/Mekanism/AE2/FD/FTB и их динамические библиотеки.

Понадобятся `C:\Games\Reimagined-r7\installed.lock.json` и SHA256 фактически установленного `mods\reimagined-0.1.0-alpha.jar`. Ожидаемый локально упакованный CoreSHA256 — `266c7e4309b6692e86498f1437b1c69c65777fb391fb6e478ae29dd7afc75451`; это значение ещё не сопоставлено с пользовательским экземпляром.

## Резервная копия перед любым запуском R8

Полностью закрыть оба клиента/мир LAN; dedicated штатно остановить командойstop. Копировать **всю папку мира**, а также R7instance/config/lock/квестовые файлы, а не один settlements.dat. Автоматические .pre-v2 copies защищают только migration settlement-data и не заменяют backup.

Пример PowerShell с реальным путём к **тестовому** миру, уникальный каталог назначения:

```powershell
$source = 'C:\PATH\TO\R7\.minecraft\saves\R7-Test'
$backup = 'C:\Games\Reimagined-Backups\R7-Test-' + (Get-Date -Format 'yyyyMMdd-HHmmss')
if (Test-Path -LiteralPath $backup) { throw 'Backup destination already exists' }
Copy-Item -LiteralPath $source -Destination $backup -Recurse -ErrorAction Stop
```

Сверить количество/размер файлов, затем отдельно проверить открытие копии в R7. Эта команда подготовлена как инструкция; в облаке пользовательский backup **не выполнялся**.

## Испытание

Новый экземплярPrism и новые миры для каждой партии. После новойгенерации отдельно открыть **копию R7тестового мира**: проверить инвентари/скиллы/исследования обоих игроков, Version2Settlers+Aggregates/NPC/торговые запасы, FTBкоманду/награды, механизмы, рецепты, старые и новые чанки, save/restart.

Новые worldgenмоды не обязаны заполнять уже сгенерированные чанки. Не запускать массовую ретрогенерацию/перегенерацию/сканирование втика. При удалении новой партии не открывать уже сохранённый еюмир в R7: безопасный откат — восстановление **исходной копии**, а не заменаJAR назад. Совместимость отката R8→R7 не обещается.

CoremodId и существующие IDs/SavedData в этомэтапе не меняются. Магическиеисследования и механизмы не конвертируются автоматически. Любая будущаямиграция — отдельная задача.
