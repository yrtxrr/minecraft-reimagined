# Почему R6 ошибочно отклоняет Minecraft[1.21,1.21.1)

Новые установочные релизы остановлены. Установщик, Core, манифесты и версии модов в этом этапе **не изменены**. Кэш пользователя R4–R6 остаётся на егоWindowsПК и из облака недоступен.

## 1. Лимит12 и порядок — собственное ограничение установщика

`Resolver.mr`: query API с loaders=[neoforge], game_versions=[1.21.1]; локальный `compatible` повторно требует точное вхождение1.21.1 иneoforge, затем `choose` допускает только разрешённыеversion_type. Версии с однимтегом1.21 без1.21.1 не проходят.

Сначала проверяется предпочтительныйJEI19.27.0.340, если он есть вответе и проходиттеги/канал; затем стабильныеrelease предпочтительнееbeta, внутриканала выбирается максимальнаяdate_published. Отклонённыйversion_id удаляется из текущего массива. Цикл искусственно ограничен12проверками. Это защита объёма загрузок, **не доказательство отсутствия всех совместимыхфайлов**. ВR5/R6 ошибка была не вмаленькомлимите сама по себе: повторныйперебор применял неверный критерийMinecraftсовместимости.

## 2. Подтверждённая первопричина — пропущенная матрица FML

NeoForge21.1.264.pom в существующем проверенном Gradlecache требует net.neoforged.fancymodloader:loader:4.0.45.

В **фактическом loader-4.0.45.jar** метод VersionSupportMatrix.static{} проверен через `javap -c -p`:
- приMinecraft[1.21.1] добавляет `mod.minecraft` альтернативу **1.21**;
- добавляет `mod.neoforge` альтернативу **21.0.166**.

`testVersionSupportMatrix` сначала вызывает стандартнуюпроверку, затем проверяет объявленныйдиапазон против этих альтернатив. Это поведение загрузчика, а не разрешение нам принимать произвольные неподходящиеверсии.

Отдельный Javaпрогон настоящего Maven3.8.5 VersionRange/DefaultArtifactVersion показал:
```
[1.21,1.21.1) against1.21.1 => false
[1.21,1.21.1) against1.21   => true
```

Поэтому прежнее «jei/moreculling исключает1.21.1, значит несовместим» было неверным заключением: оно игнорировало штатный fallback FML. Диапазон сам по себе не доказывает ни полную несовместимость, ни работоспособность JAR/API/mixins. **Это моя ошибка в критерии проверки установщика.** Увеличиватьлимит12 или продолжать вслепуюподбиратьверсии было бы неправильно.

Важно: первоначально просмотренный исходныйтег FML4.0 (48d5020…) содержит старуюматрицу1.19.2. Он **не** использован как доказательство для21.1.264; вывод основан на фактическом cached4.0.45bytecode и POM. Официальныйрепозиторий: https://github.com/neoforged/FancyModLoader .

## 3. Старый план и кэш

`--base-plan` удаляет JEI/MoreCulling изselected и locked_targets, а также их необщиезависимости; остальные записи сохраняет. Следовательно, уR6 этидвастарыхкорневыхфайла не должны молчаоставаться выбранными изплана. Кэш адресован ожидаемымофициальнымхешем; передиспользованием проверяются размер/хеш. Повторнаявыдача того жеJAR изкэша при том жеversion_id ожидаема, не повод менять или очищатькэш. ПолныйфактическийR6план пользователя ещё не получен, поэтому конкретнуюегоцепочку нельзя считать проверенной здесь.

## 4. Что ещё требуется подтвердить

Облачные официальныеAPI/CDN былиблокированы403; в этомэтапе повторно не опрашивались. Конкретные JEI/MoreCullingJAR пользователя не доступны. Нельзя сейчас честно назватьversion_id+официальныйSHA512+полныйdescriptor «проверенными в облаке». Наличиеофициальных1.21.1файлов подтверждено пользовательскимWindowsответомAPI, но этого недостаточно для бинарнойприёмки.

Нужны сыройdescriptor, modId/version, полныйнаборзависимостей, размер/хеш иversion_id конкретныхфайлов. Добавлен **только read-only диагностический скрипт** `scripts/modpack/inspect-rejected-cache.py`, безсетевыхзапросов, модификацииJAR, удалениякэша или overrideсовместимости:

```powershell
py -3 inspect-rejected-cache.py --cache C:\Games\Reimagined-r4\downloads --cache C:\Games\Reimagined-r5\downloads --cache C:\Games\Reimagined-r6\downloads --output C:\Games\Reimagined-cache-evidence.json
```

Скачать скрипт отдельно из текущейветкиGitHub или чата; длянегоPython3.11+, stdlib. Файлoutput должен быть новым. ПередатьJSON, полныйтекстотклонённыхversion_id изR6 и двасоответствующихJAR (поодномуJEI/MoreCulling; пути будут вJSON), либо минимум исходныеMETA-INF/neoforge.mods.toml иAPIметаданныефайлов. Скрипт ничего не устанавливает и не помечает runtimePASS.

Только после сопоставления этих доказательств исправлять установщик: точнаясемантика целевогоFML, регрессия с реальнымиdescriptor, безопаснаяпроверка остальныхдиапазонов и затем отдельныйновыйпрофильзапуска. Наэтомэтапе **нет оснований исключать JEI/MoreCulling как несуществующие для1.21.1**. MoreCulling при подтверждённойнеработоспособности можно оставитьнеобязательнымоптимизатором; замену рецептурногопросмотрщика рассматривать только после проверки конкретногоJEI, а не вследствие этойошибкинашегофильтра.
