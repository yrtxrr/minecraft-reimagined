## Antigravity: механика и магия

Пять изменённых Java-файлов затрагивают MechanicalBlock/MachineBlockEntity/MechanicalNetwork/MechanicalNetworks/SpellWorldAccess. С кузницей/грушами прямого пересечения реализаций нет; текстовый конфликт с основной — `PROGRESS.md`.

Положительные изменения: готовые chunk/BE lookup вместо потенциально загружающего обращения, локальный cache последнего чанка внутри обхода механики и ray view, стандартный RecipeManager.CachedCheck для жернова. Границы обходов сохранены. Кэши последнего чанка должны оставаться короткоживущими: их нельзя переносить в глобальное/долгоживущее хранилище без unload-инвалидации.

Открытые вопросы:

- У колеса полностью удалён BE ticker. Очередь MechanicalNetworks обрабатывает запросы, но сама не ставит просроченные компоненты обратно в очередь; TTL-refresh раньше инициировался также вызовом rotation из тикера колеса. Жернов продолжает запрашивать rotation даже с пустым входом. Для отдельного колеса/валов без жернова остаются onLoad, neighbor invalidation и взаимодействие игрока. Требуется отдельный тест этой топологии: изменение потока воды (в том числе изменения потока у соседней воды), редстоун, выгрузка/загрузка и возобновление вращения без клика/диагностического rotation, который сам скроет отсутствие refresh. Имеющиеся 88 тестов прошли, но это не доказательство такого сценария и не установленная клиентская регрессия.
- Обещанный в PROGRESS ранний выход для пустого жернова расположен **после** `MechanicalNetworks.rotation`, а не до него. Утверждать устранение этого обращения нельзя. Просто переносить выход выше тоже нельзя без решения владельца обновления анимации пустой сети.
- Кэш проверки редстоуна — новый HashMap на компонент за scan; он заполняется и для узлов, не являющихся жерновами. Повторные signal-query сокращаются, но добавляются выделения/map entries. Ускорение/снижение allocation без сравнения не установлено.
- CachedCheck стандартный, однако перед объединением нужны адресные проверки смены/удаления milling-рецепта после reload и нескольких перекрывающихся рецептов, включая hopper-вставку. Существующий тест reload кузницы не проверяет этот новый кэш жернова.
- Записанные Antigravity серверные замеры относятся к исходной ревизии до оптимизаций; свежего сопоставимого after-профиля нет. Нулевой JFR не доказывает измерения CPU/allocations. Не переписывать прежние неопределённые причины длинных тиков в установленный факт.
