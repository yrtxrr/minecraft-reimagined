# Переход от встроенного браузера к необязательному JEI

## Завершено: удаление собственного интерфейса

Удалены RecipeBrowserScreen, InventoryRecipePanel и RecipeCatalog, включая автоматическую регистрацию ScreenEvent/RecipesUpdatedEvent/LoggingOut. Больше нет бокового каталога, кнопки R, перехвата R/U, собственной навигации/поиска/пагинации и клиентского кэша. Удалены BrowserItems, BrowserSnapshotCache, navigation/BrowserHistory/BrowserPages/BrowserSearch и только их устаревшие тесты:4JUnit и4GameTests. Файлов текстур собственного браузера не было: панель рисовалась кодом. Удалены17неиспользуемых ключей локализации; журнал/подсказки больше не обещают существование встроенного браузера.

BrowserRecipes, RecipeDisplay, RecipeDisplayAdapter и ShulkerColorDisplays сохранены как общие read-only проекции реальных рецептов, покрытые серверными тестами. Они не регистрируют интерфейс, события или игровой тик и сами не запускаются в клиенте. Оставшиеся ключи reimagined.browser.*_note относятся к метаданным этих проекций. Это не работающий просмотрщик и не JEI-плагин.

Все рецепты/data packs, RecipeType/Serializer, станки, меню станков, предметы и механики сохранены. Четыре CreativeModeTab изcb4cbc2не переделывались. Ванильная книга рецептов остаётся доступна; без стороннего мода отдельного каталога рецептов теперь нет.

## Подготовлено: opt-in запуск настоящего JEI

В build.gradle добавлен только отключённый по умолчанию dev opt-in:

```
source scripts/cloud-shell.sh
./gradlew runClient -PwithJei -PjeiVersion=<подтверждённая опубликованная версия 19.x.y.build>
```

Официальные координаты:mezz.jei:jei-1.21.1-neoforge. Репозиторий ограничен группами mezz.jei/net.mezzdev.config. Без -PwithJei нет запроса к Maven JEI или JEI-зависимости. Без точной версии opt-in завершается понятной ошибкой, а не выбирает неподтверждённый latest. Runtime dependency не встраивается в JAR, в neoforge.mods.toml нет обязательного JEI. Это подготовка загрузки dev-мода, **не завершённая интеграция**.

Изучен официальный исходный код https://github.com/mezz/JustEnoughItems/tree/4a9042f579f4602ff21827dd873cffe57329473d (ветка1.21.1, MIT):minecraftVersion1.21.1, NeoForge21.1.251, минимальный NeoForge21.1.238. Наш21.1.264попадает в заявленный исходниками диапазон. specificationVersion19.70.0— версия исходной ветки, не подтверждение доступного номера опубликованной сборки. Конкретный released JAR/его метаданные и фактическая совместимость пока не проверены.

Нужен разрешённый HTTPS CONNECT к maven.blamejared.com:443для metadata, POM/module и JAR выбранной опубликованной версии. При последующей разработке плагина также нужны официальные jei-1.21.1-common-api и jei-1.21.1-neoforge-api той же версии, только compileOnly. Нужна настройка разрешённых доменов среды/прокси; токен GitHub, отключение TLS или альтернативный обходной прокси не нужны и не использовались. Ранее запросы расширенного разрешения были отменены. Загрузка через неофициальные зеркала не выполнялась.

## Остаётся после открытия доступа

1. Получить metadata и закрепить точную опубликованную версию, проверить её NeoForge/Minecraft metadata и обязательные зависимости.
2. CompileOnly API + отдельный клиентский @JeiPlugin; вне JEI не загружать API-классы и не регистрировать собственный оверлей.
3. Обычный крафт/печи/ванильный smithing/brewing оставить встроенным категориям JEI. Не дублировать их общими проекциями.
4. Категории реальных процессов:помол(MillingRecipe), котелок(CookingRecipe), исследования/алтарь(MagicRecipe), кузница(ForgingRecipe). Показывать настоящие ingredients/results, обязательные миски/фокусы/инструменты, нагрев/время и станции; динамическую кузнечную обработку не выдавать за фиксированный итоговый компонент. Авторитет изготовления остаётся серверным.
5. Проверить R/U, поиск, локализацию, обновление после /reload, подключение/выход и открытия исследований. JEI должен владеть жизненным циклом своего каталога; не возрождать старый UI/cache.
6. Запустить реальный клиент с JEI и без него. До этого не заявлять о проверенном отображении пользовательских процессов в JEI.
