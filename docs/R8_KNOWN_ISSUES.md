# R8: текущие блокеры

1. Блокер baseline снят: получен полный R7lock53артефактов, CoreSHA совпадает с R7. Прямое чтение всех WindowsJAR и миров/сохранений/двухклиентов остаётся непроведённым; готовность R8 не заявлена.
2. Ни у одного из20кандидатов пока не подтверждены одновременно конкретнаяофициальнаяпубликация, дата, SHA256, реальныйdescriptor/closure и применимость к фактическомуR7. Это UNVERIFIED/DEFERRED, не фиктивный PASS.
3. Aeronautics — приоритет, но требуется первичныйофициальныйрелиз/лицензия/полнаяSable/Simulated/Offroadцепочка. Косвенная ссылка в другойинтеграции не заменяет её. Gadgets/Airliners без идентичности остаются за воротами E1.
4. Steam ’n’ Rails просмотрен для1.20.1; MythicBotany — Forge1.20.1. Эти исходники ставить нельзя. Отсутствие другого совместимогорелиза не доказано.
5. MyNether требует FD>=1.3.2; в предоставленномR7 FD1.21.1-1.3.4, предварительно подходящее семейство. Финальная проверка actualdescriptor/рецептов остаётся; скрытых обновлений FD/Core не делать.
6. EnchantmentIndustry требует DragonsPlus; ExtendedAE — Glodium/GuideME/JarJarAPI. Их нельзя пропустить из closure. Python-аудит R7 не нормализует регистрtype: требуется адресное исправление в R8 после исследования, до партииB, срегрессией на реальныйdescriptor. На этапе исследования установщик R7 не изменялся.
7. ExpandedDelight содержит неоднозначности build/descriptor/placeholder; лицензия MDKшаблона не доказывает лицензию всех ресурсов. Требуется конкретныйJAR/полныйlicense.
8. Thaumcraft личноеиспользование/перераспространение оригинальныхресурсов и облачные Maven403; Botania порт не гарантирует ABI для MythicBotany. Существующий MagicLab ещё неruntimeпроверен. ArsNouveau не является заменой и запрещён.
9. ГрафическийR8клиент, миры/сохранения/сервер/дваигрока/производительность NOT_TESTED. BaselineR7mainmenu — не приёмка этих систем.

Разрешения пользователя на обычную разработку/коммиты достаточно. Нужна недостающая фактическая информация, а не повторное утверждение плана. Следующий безопасный шаг — получить metadata конкретных новых JAR и выбрать одну партию с полными доказательствами; не расширять Core пока базовыеаддоны не объединены.
