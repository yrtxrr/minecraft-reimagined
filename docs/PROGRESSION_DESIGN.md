# PROGRESSION_DESIGN.md — Технологическая progress Reimagined Core

## Обзор

Единая система прогрессии technologies, магии и RPG, построенная на семи этапах развития и интегрированная с FTB Quests, Pufferfish's Skills и существующими модами модапака.

Эта система не переопределяет предметы или механики установленных модов. Она только упорядочивает доступ через квестовую книгу, навыки и рецепты.

## Семь этапов прогрессии

| Этап | Название | Фокус |
|------|----------|-------|
| I | Выживание и первые инструменты | Дерево, камень, еда, базовое оружие |
| II | Металлургия и обработка материалов | Руды, плавка, сплавы, базовое кузнечное дело |
| III | Механизация и водяная/ветряная энергия | Create водяные колёса, вал, мельница |
| IV | Промышленность и тяжёлые машины | Immersive Engineering, Mekanism базовые машины |
| V | Электричество, химия и сложное производство | Mekanism++, AE2 базовая сеть, электроэнергия |
| VI | Компьютеры, цифровые сети и автоматизация | CC: Tweaked, AE2 продвинутая автоматизация |
| VII | Передовые материалы и масштабная инженерия | AE2 сеть, Mekanism современное производство, магиотехника |

## Техническая реализация

### Энергетические системы (не унифицировать)

Каждая энергетическая система остаётся уникальной для своего мода:

- **Create** — кинетическая энергия (вращательная сила), водяные/ветряные колёса, вал, шестерни.
- **Immersive Engineering** — kinetic energy (доп. передачи), водяные/ветряные генераторы.
- **Mekanism** — 열/энергия, химия, инфузоры.
- **AE2** — электричество (AE2 энергия), сеть хранения/кристаллы.
- **CC: Tweaked** — компьютеры, периферия,_redstone_ автоматизация.

Не создаём свою общую энергетическую систему. Каждый мод сохраняет свою. Прогрессия только определяет, в каком порядке игрок открывает доступ к рецептам и квестам.

### Металлы и руды

- Ванильное железо, золото, медь, алмаз сохраняются без изменений.
- Create/IE/Mekanism вставляют свои руды и сплавы через дата-пак/конфиг мода, не заменяя ванильные.
- Прогрессия ограничивает *доступ* к рецептам через FTB Quests задачи (Item requirement, Advancement, Custom), а не через удаление рецептов.

### Рецепты

Все рецепты остаются в datapack (json). Прогрессия не добавляет новых Java-классов рецептов. Только:

1. KubeJS скрипты для отключения/скрытия дублирующих рецептов (по согласованию с Codex).
2. FTB Quests задачи, проверяющие наличие предметов и продвижение этапов.
3. Существующий `MillingRecipe` контракт продолжает использоваться для молотковых процессов.

### Компоненты

Промежуточные компоненты ( шестерни, кабели, платы ) не дублируются. Каждый мод использует свои. Прогрессия не добавляет новых компонентов.

## Интеграция с навыками (Pufferfish's Skills)

Существующие девять деревьев навыков (WARRIOR, ARCHER, MAGE, ALCHEMIST, ENGINEER, MINER, SMITH, FARMER, SAILOR, MERCHANT) сохраняются. Прогрессия не добавляет новых деревьев. Навыки не блокируют использование инструментов — только дают бонусы.

## Интеграция с FTB Quests

Каждый этап соответствует группе глав в квестовой книге (см. docs/QUEST_BOOK_DESIGN.md). Квесты проверяют:

- Получение предметов (Item task)
- Достижения (Advancement task)
- Позицию/биом (Location, Biome)
- Использование предметов/блоков (Use item/block)
- Custom условия через Reimagined Core события

Не проверяем сотни условий каждый тик. Используем события и асинхронную проверку с ограниченной частотой.

## Дублирование (устранить, но сохранить уникальность)

| Что дублируется | Что сохраняется |
|-----------------|-----------------|
| Железо/медь/золото руды | Ванильное железо не удаляется |
| Каменная дробилка/дробление | Create дробление остаётся уникальным |
| Энергетические системы | Каждая система мода уникальна |
| Базовые инструменты | Ванильные инструменты остаются |

## Не в scope этого этапа

- Не удалять рецепты модов без согласования.
- Не добавлять обязательную зависимость от Create/IE/Mekanism/AE2/CC.
- Не создавать новую энергетическую систему.
- Не блокировать инструменты без прокачки навыков.

## Зависимости от Codex

Требуются согласованные API Reimagined Core для:

1. Событий прогрессии (этап разблокирован, навык повышен).
2. Регистрации квестовой книги (FTB Quests chapters через Java или datapack).
3. Проверки рецептов без прямой зависимости от модов.

Пока API не готовы: подготовить проектирование и независимые данные (JSON квестов, языковые файлы), не затрагивая общие классы.

## Метрики и производительность

- Проверка квестов через события, не через тик-скан world.
- Кэш прогрессии игрока в PlayerPersistentData (существующий паттерн PlayerSkills).
- Нет сканирования всех чанков/сущностей каждый тик.

## Локализация

Все названия этапов, описания, подсказки — в en_us.json и ru_ru.json под префиксом `progression.reimagined.*`.
